# 网络监督的细粒度图像识别 — 技术方案

> 赛题：网络监督的细粒度图像识别（Webly-Supervised Fine-Grained Image Recognition）
> 团队：上海理工大学
> 日期：2026 年 6 月

---

## 一、算法概述

本方案针对网络监督条件下的 ImageNet-1K 图像分类任务，核心挑战在于训练数据中存在标签噪声、类别长尾分布和网络数据偏差。我们以 ResNet-50 为主干网络从零训练，**最终方案以完整数据增广 recipe（Mixup + CutMix + RandAugment + RandomErasing）+ 交叉熵 + 标签平滑为核心**，配合混合精度训练、梯度累积、EMA 等工程优化适配单卡 RTX 4090D 硬件。当前 Baseline 已达 **Top-1 77.53% / Top-5 93.63%**（100 epochs, EMA, 仅 RRC+HFlip 弱增广），全增广版本 mixup_v2 训练中（预计 78–80%）。方案特点为：(1) 通过 ablation 系统性证伪鲁棒损失（SCE/GCE）在本任务弱噪场景下的有效性；(2) 严格单变量消融保证归因干净；(3) 推理端集成 + TTA 进一步榨取增益；(4) 完整的 Docker 可复现流程。

## 二、实现方案

### 2.1 解题思路

**问题分析：**

网络监督数据的三大挑战：
1. **标签噪声**：网络爬取的图像标签存在错误，估计整体噪声率约 5-15%，部分类别（如 radio、modem）噪声率高达 60%
2. **长尾分布**：1000 个类别的样本数量不均衡，头部类别约 1300 张，尾部类别可能不足 500 张
3. **数据偏差**：网络图像与标准 ImageNet 验证集的分布存在域偏移

**整体方案框架：**

```
数据分析 → 噪声估计 → Loss 选择 → 模型训练 → 测试推理
   ↓           ↓          ↓          ↓          ↓
类别分布   Top-20噪声类  SCE/GCE   ResNet-50   result.csv
长尾分析   噪声率估算    对比实验   100 epochs  格式校验
```

### 2.2 数据处理

**数据集规模：**
- 训练集：1,281,167 张图像，1000 个类别
- 验证集：50,000 张图像（每类 50 张）
- 测试集：100,000 张图像（需预测）

**数据质量分析：**
- 损坏文件：0 张
- 近空白图：0 张
- 极小图：约 50 个类各有 1-3 张（128 万张中的几十张，可忽略）
- 高噪声类别：radio（~60%）、modem、spatula 等标签歧义严重

**数据增强方案：**
- 基础增强（baseline_v1 使用）：RandomResizedCrop(224) + RandomHorizontalFlip
- 进阶增强（mixup_v2 使用）：RandAugment(N=2, M=9) + RandomErasing
- 正则化增强（mixup_v2 使用）：Mixup(α=0.2) + CutMix(α=1.0)，mixup_prob=0.5（50% 概率走 mixup，50% 走 cutmix）
- 实测：30ep schedule 下 mixup-only 比纯 CE+LS 提升 **+3.15%**（69.78 vs 66.63），是单技术最大增益项

### 2.3 算法设计与开发

**Backbone 选择：**

| 模型 | 参数量 | 从零训练 Top-1 | 100ep 训练时间(4090D) | 选择理由 |
|------|--------|---------------|----------------------|---------|
| StarNet-S2 | 12M | ~68% | ~1.5 天 | 快速实验筛选用 |
| **ResNet-50** | 25M | **77.53%（实测）** | **~55h（实测 33min/ep）** | **主力模型，稳定可靠** |
| ConvNeXt-V2-T | 28M | ~79-81% | ~4 天 | 备选冲刺模型 |

选择 ResNet-50 作为主力模型的理由：
1. 训练稳定性高，从零训练有大量参考基准
2. 约 2.3 天可完成 100 epoch，允许多次实验迭代
3. 参数量适中，RTX 4090D 可用 batch=128 + 梯度累积 2 步

**噪声鲁棒损失函数（实验对比）：**

| 损失函数 | 核心思想 | 实测超参 | 40ep val_top1 | 结论 |
|---------|---------|---------|--------------|------|
| CE + Label Smoothing | 软化标签分布 | smoothing=0.1 | 66.63 | **基线** |
| SCE | 对称化 CE，抑制噪声梯度 | α=0.5, β=0.5 | 66.63 | 与 CE 完全持平，零增益 |
| SCE（极端配置） | 同上 | α=0.1, β=1.0 | 60.66 | β 过大反而退化 |
| GCE | 截断大 loss 样本梯度 | q=0.7 | 26.01（崩） | 早期梯度被压扁，warmup 不足 |
| ELR | 历史预测正则化 | β=0.9, λ=3.0 | 未实验 | 需样本级记忆，成本高 |

**关键结论**：本任务数据噪声率较低（约 5–15%），SCE/GCE 这类为 40%+ 高噪声率设计的损失函数无法发挥优势，作为"鲁棒损失在弱噪场景下未见增益"的负样本结论。后续算力全部转向数据增广方向（Mixup/CutMix），实测增益显著。

**训练策略：**
- 优化器：SGD + Momentum(0.9) + Weight Decay(1e-4)
- 学习率：Warmup(5ep, linear) → Cosine Annealing
- 混合精度：AMP(FP16) 减半显存占用
- 梯度累积：2 步，等效 batch size = 256
- EMA：decay=0.9999，用于验证和最终推理
- 梯度裁剪：max_norm=5.0

### 2.4 模型训练与优化

**RTX 4090D 训练优化：**
- TF32 加速：`torch.backends.cuda.matmul.allow_tf32 = True`
- cuDNN Benchmark：`torch.backends.cudnn.benchmark = True`
- Channels Last 内存格式：显存节省 ~10%
- AMP 自动混合精度：显存减半，速度 ~2x
- DataLoader 优化：num_workers=4, pin_memory=True
- 实测单 epoch 耗时：~33 分钟（batch=128, accum=2, 全量 128 万张）

**实验流程（快速筛选 → 正式训练）：**
1. StarNet-S2 + 10% 子集 + 30 epochs：快速对比不同 Loss（~30 分钟/组）
2. ResNet-50 + 10% 子集 + 30 epochs：确认最优 Loss 在大模型上的表现
3. ResNet-50 + 全量数据 + 100 epochs：正式训练（~55h on 4090D）

**超参搜索空间：**
- 学习率：{0.05, 0.1, 0.2}
- SCE α：{0.1, 0.3, 0.5}
- SCE β：{0.5, 1.0}
- GCE q：{0.5, 0.7, 0.9}

### 2.5 消融实验汇总（核心结果）

**统一对比表（截至 2026-05-26）：**

| 实验 ID | Backbone | 增广 | Loss | Schedule | val_top1 | 备注 |
|--------|---------|------|------|---------|---------|------|
| baseline_v1 | ResNet-50 | RRC+HFlip | CE+LS 0.1 | 100ep | **77.53** | 基线（已收敛） |
| rerun30_ce_ls01 | ResNet-50 | RRC+HFlip | CE+LS 0.1 | 40ep | 66.63 | 短 schedule 锚点 |
| rerun30_sce_a05_b05 | ResNet-50 | RRC+HFlip | SCE α=0.5,β=0.5 | 40ep | 66.63 | **与 CE 持平，零增益** |
| rerun30_sce_a01_b10 | ResNet-50 | RRC+HFlip | SCE α=0.1,β=1.0 | 40ep | 60.66 | β 过大反而退化 |
| rerun30_gce_q07 | ResNet-50 | RRC+HFlip | GCE q=0.7 | 40ep | 26.01 | **崩**，需调 LR/warmup |
| mixup_only_e30 | ResNet-50 | RRC+HFlip+Mixup α=0.2 | CE+LS 0.1* | 30ep | **69.78** | 单技术最大增益 |
| cutmix_only_e30 | ResNet-50 | RRC+HFlip+CutMix α=1.0 | CE+LS 0.1* | 30ep | 69.12 | 与 mixup 近似 |
| **mixup_v2**（训练中）| ResNet-50 | **全增广** | CE+LS 0.1（Bug#1 修复） | 100ep | **TBD** | 预期 78–80% |

> \*：注意 mixup_only_e30 / cutmix_only_e30 训练时 Bug #1 未修，LS 实际未生效；这两组的成绩反映"+Mixup/CutMix −LS"复合效应。mixup_v2 是 Bug #1 修复后的干净版本。

**关键判断：**
1. **鲁棒损失路线（SCE/GCE）在本任务无效**：4 组实验，最好仅与 CE 持平，最差直接崩。算力转向数据增广方向。
2. **Mixup/CutMix 才是增益主力**：30ep schedule 下已比 40ep 的 CE+LS 高 3 个点；mixup_v2（100ep + 全增广 + Bug#1 修复）预期可与 baseline 形成"完整增广 recipe 合力"的干净归因对比。
3. **推理端集成增益独立叠加**：baseline_v1 + mixup_v2 两个 recipe 差异大，集成预期再 +0.5–2.0%。

### 2.6 测试与验证

**验证集评估：**
- 使用 EMA 模型进行验证（比原始模型更稳定）
- 指标：Top-1 Accuracy、Top-5 Accuracy
- 每 epoch 评估一次，保存最优 checkpoint

**测试集推理流程：**
```
加载 best.pth（自动取 EMA 字段）→ HFlip TTA → 多模型 logit 平均 → argmax → result.csv
```

**推理端增益策略（predict.py 已实装）：**
- **HFlip TTA**：每张图水平翻转后再前向一次，softmax 平均；推理时间 ×2，预期 +0.2–0.5% top-1
- **多模型集成**：`baseline_v1.pth` + `mixup_v2.pth` 等权 softmax 平均，两模型 recipe 差异大、相关性低，预期 +0.5–1.5% top-1
- **CPU logits 累加器**：10 万 × 1000 × 4B ≈ 400MB，避免 GPU OOM
- **AMP autocast** 默认开启，10 万张全量推理预计 3–5 分钟

调用示例：
```bash
python scripts/predict.py \
  --config configs/imagenet_resnet50.yaml \
  --checkpoint checkpoints/baseline_v1/best.pth checkpoints_mixup_v2/best.pth \
  --tta hflip \
  --output submit/result.csv
```

**CSV 格式：**
```
image_00001.JPEG,0386
image_00002.JPEG,0721
...
```
每行为 `filename,4位数字类别编号`，共 100,000 行。

## 三、算法创新点

1. **系统性证伪鲁棒损失**：通过 SCE（α=0.5/β=0.5、α=0.1/β=1.0 两组）+ GCE（q=0.7）共 4 组对比实验，证明在弱噪场景（噪声率 5–15%）下鲁棒损失相对 CE+LS 零增益甚至退化，为 webly-supervised 任务的损失函数选型提供了反例参考
2. **严格单变量消融保证归因干净**：发现并修复 trainer 中 mixup 路径下 label_smoothing 静默失效的 bug，使 baseline_v1（CE+LS, 弱增广）与 mixup_v2（CE+LS, 全增广）的 loss 计算路径完全等价，差异 100% 归因于"完整增广 recipe 合力"
3. **推理端零额外训练成本增益**：predict.py 集成 HFlip TTA + 多模型 softmax 平均，组合 baseline_v1 + mixup_v2 两个 recipe 差异大的模型，预期再榨取 0.5–2.0% top-1
4. **快速筛选实验范式**：利用轻量级 StarNet（12M 参数）在 10% 子集上快速验证策略有效性，再迁移到 ResNet-50 全量训练，实验效率提升 10x
5. **工程化可复现方案**：完整的 Docker 容器化 + 一键复现脚本，确保从训练到推理的全流程可复现

## 四、问题与思考

### 开发过程中遇到的困难及解决方案

| # | 问题 | 影响 | 解决方案 |
|---|------|------|---------|
| 1 | Docker 构建上下文不支持 `../` 相对路径 | 赛事方无法复现 | Dockerfile 移至仓库根目录，所有 COPY 相对根路径 |
| 2 | run.sh 引用不存在的配置文件 | 容器启动即失败 | 改为环境变量 CONFIG 读取，提供默认值 |
| 3 | GitHub HTTPS 被 TLS 重置 | 无法协作推送代码 | 切换 SSH 走 443 端口（ssh.github.com:443） |
| 4 | 依赖未锁版本，torch 2.6 接口漂移 | 跨机器行为不一致 | requirements.txt 加上下界约束 |
| 5 | 10% 子集数据准备脚本 val 目录缺失 | 训练 pipeline 验证集评估失败 | 用 LOC_val_solution.csv 重建 val 的类别子文件夹结构 |
| 6 | autodl-tmp1 上 train 只解压了 123/1000 类 | 模型只能学到 12.3% 的类别 | 统一数据源，symlink 到完整的 1000 类数据 |
| 7 | StarNet config 的 num_classes 设为 123 | 模型输出维度与实际类别数不匹配 | 修正为 1000 |
| 8 | EMA 权重未同步 BatchNorm running stats | EMA 模型 val 精度异常偏低 | `ema.update()` 中增加 buffer 逐一 copy |
| 9 | Checkpoint resume 只恢复 model+EMA | 中断后重训 LR 从头 warmup，浪费算力 | `load_checkpoint` 完整恢复 optimizer/scheduler/scaler/best_acc |
| 10 | **Bug #1**: mixup 路径下 `label_smoothing` 完全失效 | mixup 系列实验配置 `smoothing=0.1` 静默失效，与 baseline 对比时变量不可控 | 在 mixup 分支显式注入 LS：`mixed_targets * (1-eps) + eps/num_classes` 再 log_softmax + NLL |
| 11 | **Bug #2**: `cudnn.deterministic=True` 与 `benchmark=True` 同时设置 | benchmark 实际不生效，100ep 慢 5–15%（约 2–7h） | `seed.py` 统一改为 `deterministic=False, benchmark=True`，trade off bit-exact 复现换速度 |
| 12 | **Bug #3**: resume 加载旧 scheduler state 到新 schedule | mixup_e100_resume 从 ep30 续训，cosine 进入上升半周期，LR 反向爬回 0.1 把权重炸毁 | 待修：增加 `cfg.training.resume_mode: "finetune"`，只 load model+ema，不碰 optimizer/scheduler |
| 13 | mixup_e100_resume 整体崩盘（val 72.51→12.64%） | 70h 算力浪费 | 根因即 Bug #3；改为重头跑 100ep（mixup_v2），代价 +15h 但与 baseline 同 schedule 可比性 100% |

### 进一步优化思考

- Docker 构建层缓存优化：先 COPY requirements.txt 再 pip install，源码变动不触发重装
- WandB 离线模式适配无外网赛事机器
- 考虑 Mixup/CutMix 集成到训练循环中进一步提升泛化能力
- 长尾分布可尝试 ClassBalancedSampler 或 focal loss 变体
