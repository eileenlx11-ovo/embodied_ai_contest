# 网络监督的细粒度图像识别技术方案

> 赛题：网络监督的细粒度图像识别
> 任务：ImageNet-1K ResNet-50 从零训练分类
> 团队：上海理工大学
> 日期：2026 年 6 月

---

## 一、算法概述

本方案面向含噪网络监督场景下的 ImageNet-1K 图像分类任务。在不使用预训练模型、不引入额外数据、不进行多模型集成的约束下，我们采用 ResNet-50 从零训练，以交叉熵、标签平滑、EMA、余弦学习率和轻量级 Mixup/CutMix 为核心。最终提交路线为 **完整训练集 + ResNet-50 + CE/Label Smoothing + Mixup(α=0.1) + CutMix(α=1.0) + raw/EMA 双评估选优 + 单模型 HFlip TTA**。

验证集结果显示，基础配方达到 Top-1 **77.53%**，最终 full_mixcut 配方达到普通验证 Top-1 **77.57%**，在同一模型 checkpoint 上使用 HFlip TTA 后达到 Top-1 **77.99%**、Top-5 **93.97%**。方案的核心判断是：本数据集整体噪声较弱，显式剔除样本和强鲁棒损失不一定优于保留数据覆盖度；温和的 label-space 增强更适合作为噪声鲁棒正则。

## 二、实现方案

### 2.1 赛题约束与设计原则

赛题提供 ImageNet-1K 训练集、验证集和测试集，规模如下：

| 集合 | 数量 | 用途 |
|---|---:|---|
| Train | 1,281,167 | 从零训练 |
| Validation | 50,000 | 模型选择与消融 |
| Test | 100,000 | 生成最终 CSV |

关键约束包括：不能使用预训练模型，不能引入外部数据，最终结果只能对应一个模型。我们的设计原则为：

1. **优先建立可复现强基线**：ResNet-50 是从零训练的稳定主干，训练成本和收敛行为可控。
2. **噪声鲁棒以温和正则为主**：在弱噪声场景中，避免过早依赖复杂鲁棒损失或大规模删样本。
3. **所有收益必须能被消融解释**：每条路线保留训练日志、配置和 checkpoint 元数据。
4. **最终提交保持单模型**：HFlip TTA 只对同一个 checkpoint 前向两次，不构成多模型集成。

### 2.2 数据处理与噪声分析

初步扫描显示，训练集中损坏文件和近空白图像不是主要问题，主要挑战来自类别语义歧义和网络标签噪声。例如 radio、modem、spatula 等类别存在较高视觉混淆或语义混杂。类别数量分布并非严重长尾，因此没有采用重采样或 class-balanced loss 作为主路线。

我们尝试过 C1/C2 清洗路线，包括剔除明确双类冲突样本、同形异义类别样本以及 teacher-loss 高损样本。清洗脚本加入了 exclude 文件 sanity check、teacher checkpoint key 兼容、per-class 删除上限和 merge 输入校验，保证清洗列表可复现。但完整训练结果表明，清洗数据的 Top-1 为 **76.84%**，低于 full baseline 和 full_mixcut。该结果说明：在本任务中，直接删除高 loss 样本可能同时删除了困难但有效的训练样本，损害数据覆盖度。

### 2.3 模型结构

主模型为标准 ResNet-50，类别数为 1000。选择 ResNet-50 的理由是：

| 模型 | 参数量 | 优点 | 本项目定位 |
|---|---:|---|---|
| StarNet-S2 | 约 12M | 训练快 | 早期快速筛选 |
| ResNet-50 | 约 25M | 稳定、可复现、从零训练成熟 | 最终提交主模型 |
| ConvNeXt-V2-T | 约 28M | 潜在上限更高 | 算力充足时的备选 |

最终路线未使用预训练权重。模型输出 1000 类 logits，训练和验证均严格按照 ImageNet-1K 类别索引进行。

### 2.4 训练策略

基础训练策略如下：

| 模块 | 设置 |
|---|---|
| Loss | Cross Entropy + Label Smoothing 0.1 |
| Optimizer | SGD, momentum 0.9, weight decay 1e-4 |
| LR schedule | 5 epoch linear warmup + cosine decay |
| Epochs | 100 |
| Batch | per-step batch 128, grad accumulation 2, effective batch 256 |
| Precision | AMP mixed precision |
| Regularization | EMA decay 0.9999, grad clip 5.0 |
| Hardware | 单卡 RTX 4090D |

最终 full_mixcut 配方只加入 batch-level label-space 增强：

| 增强 | 参数 | 说明 |
|---|---|---|
| RandomResizedCrop | 224 | 基础空间增强 |
| RandomHorizontalFlip | p=0.5 | 基础空间增强 |
| Mixup | α=0.1 | 样本和标签线性混合，缓解硬标签噪声 |
| CutMix | α=1.0 | 图像区域级混合，增强局部判别鲁棒性 |
| mixup_prob | 0.5 | 两者同时启用时，50% batch 使用 Mixup，50% 使用 CutMix |
| RandAugment / RandomErasing | 不启用 | 100 epoch 预算下强增广收敛不足 |

Mixup/CutMix 的 target 采用 one-hot 后混合，再叠加 label smoothing。这样能够把原始 one-hot 硬标签转成软标签，降低噪声标签对单一样本梯度的支配强度。CutMix 实现中对输入图像使用 clone 后贴 patch，避免 in-place 修改影响后续数据路径。

### 2.5 EMA 与双评估模型选择

早期 baseline 只使用 EMA 模型验证。复盘发现，EMA decay=0.9999 在 100 epoch cosine 末段可能滞后于 raw model，尤其当学习率快速降低时，raw 权重反而可能是当前最优。因此 trainer 中实现了 raw + EMA 双评估：

1. 每个 epoch 同时验证 raw model 和 EMA model。
2. 分别保存 `best_raw.pth`、`best_ema.pth`。
3. 全局 `best.pth` 保存当轮更高者，并记录 `best_source`。
4. `evaluate.py` 和 `predict.py` 根据 `best_source` 自动加载 raw 或 EMA 权重。

最终 full_mixcut 的最佳 checkpoint 为：

```text
checkpoints_full_mixcut/best.pth
epoch=100
best_source=raw
best_acc=77.57
best_raw_acc=77.57
best_ema_acc=77.438
```

这说明 dual-eval 避免了“raw 已超过 EMA，但推理仍加载 EMA”的精度损失。

### 2.6 推理与提交

最终推理使用单个 checkpoint：

```bash
python scripts/predict.py \
  --config configs/imagenet_resnet50_full_mixcut.yaml \
  --checkpoint checkpoints_full_mixcut/best.pth \
  --tta hflip \
  --output submit/result.csv
```

HFlip TTA 流程为：原图前向一次、水平翻转图前向一次，对同一模型的两次 softmax 结果求和后取 argmax。该方法不使用额外模型，不属于多模型集成。验证集 TTA 结果为：

| 推理方式 | Val Top-1 | Val Top-5 | 增益 |
|---|---:|---:|---:|
| Plain | 77.57 | 93.77 | - |
| HFlip TTA | 77.99 | 93.97 | +0.42 pp Top-1 |

最终 CSV 为 `submit/result.csv`，共 100,000 行，已通过格式校验：每行包含 `filename,四位类别编号`。

## 三、算法创新点

### 3.1 弱噪声场景下的路线选择

我们没有简单套用高噪声标签学习中的强鲁棒损失，而是通过实验判断噪声强度和训练预算。SCE/GCE 在当前设置下没有超过 CE+LS，GCE 甚至发生明显退化，说明本赛题更接近“弱噪声 + 大规模数据覆盖”场景。

### 3.2 Mixup/CutMix 作为隐式噪声鲁棒监督

相比直接删除高 loss 样本，Mixup/CutMix 保留所有训练样本，同时把监督信号从硬标签变成软标签。它们通过 vicinal risk minimization 降低单个错误标签对参数更新的影响，适合作为网络监督数据的温和鲁棒策略。

### 3.3 raw/EMA 双评估的 checkpoint 选择

EMA 通常提高稳定性，但不是所有 epoch 都优于 raw model。最终 full_mixcut 的最优源是 raw，这证明双评估不是冗余功能，而是直接影响最终模型选择。

### 3.4 负结果驱动的工程闭环

项目保留了 mixup_v2 全强增广、C1/C2 清洗、SCE/GCE 损失等负结果。它们帮助我们排除在 100 epoch 预算下不合适的路线，最终收敛到更简单、可复现、验证更强的方案。

## 四、问题与思考

| 问题 | 观察 | 处理与思考 |
|---|---|---|
| 强增广收敛不足 | Mixup+CutMix+RandAugment+RandomErasing 的 100ep 结果为 76.91，低于 baseline | 该配方更接近长 schedule recipe，100ep 下去掉 RandAugment 和 RandomErasing |
| 数据清洗未带来收益 | cleaned_v1 Top-1 为 76.84 | 高 loss 样本可能包含有效困难样本，删除会降低覆盖度 |
| 鲁棒损失无收益 | SCE 持平或退化，GCE 崩盘 | 弱噪声下 CE+LS 已足够强，复杂损失会增加调参成本 |
| EMA 末段滞后 | full_mixcut raw 77.57，高于 EMA 77.438 | 使用 raw/EMA dual-eval 和 `best_source` 元数据 |
| 复现交付 | 需同时交付训练、验证、预测、Docker 与报告 | 以 `best.pth` 为最终模型，`latest.pth` 仅用于 resume，不作为提交权重 |

进一步改进方向包括：在不使用额外数据的前提下尝试更长 schedule、轻量 RandAugment、ConvNeXt 类主干，或对高噪声类别做“软权重”而非直接删样本。
