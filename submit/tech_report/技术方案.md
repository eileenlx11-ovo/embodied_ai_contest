# 网络监督的细粒度图像识别 — 技术方案

> 赛题：网络监督的细粒度图像识别（Webly-Supervised Fine-Grained Image Recognition）
> 团队：上海理工大学
> 日期：2026 年 6 月

---

## 一、算法概述

本方案针对网络监督条件下的 ImageNet-1K 图像分类任务，核心挑战在于训练数据中存在标签噪声、类别长尾分布和网络数据偏差。我们提出基于噪声鲁棒损失函数的从零训练方案：以 ResNet-50 为主干网络，结合对称交叉熵损失（SCE）处理标签噪声，配合混合精度训练、梯度累积等工程优化适配单卡 RTX 4060 硬件约束。方案特点为：(1) 系统性的噪声分析指导损失函数选择；(2) 轻量级 StarNet 快速筛选策略降低实验成本；(3) 完整的 Docker 可复现流程。

## 二、实现方案

### 2.1 解题思路

**问题分析：**

网络监督数据的三大挑战：
1. **标签噪声**：网络爬取的图像标签存在错误，估计整体噪声率约 5-15%，部分类别（如 radio、modem）噪声率高达 60%
2. **长尾分布**：1000 个类别的样本数量不均衡，头部类别约 1300 张，尾部类别可能不足 500 张
3. **数据偏差**：网络图像与标准 ImageNet 验证集的分布存在域偏移

**整体方案框架：**

```
数据分析 → 噪声估计 → Loss 选择 → 模型训练 → 测试推理
   ↓           ↓          ↓          ↓          ↓
类别分布   Top-20噪声类  SCE/GCE   ResNet-50   result.csv
长尾分析   噪声率估算    对比实验   100 epochs  格式校验
```

### 2.2 数据处理

**数据集规模：**
- 训练集：1,281,167 张图像，1000 个类别
- 验证集：50,000 张图像（每类 50 张）
- 测试集：100,000 张图像（需预测）

**数据质量分析：**
- 损坏文件：0 张
- 近空白图：0 张
- 极小图：约 50 个类各有 1-3 张（128 万张中的几十张，可忽略）
- 高噪声类别：radio（~60%）、modem、spatula 等标签歧义严重

**数据增强方案：**
- 基础增强：RandomResizedCrop(224) + RandomHorizontalFlip
- 进阶增强（可选）：RandAugment(N=2, M=9)、ColorJitter、RandomErasing(p=0.25)
- 正则化增强（待集成）：Mixup(α=0.2)、CutMix(α=1.0)

### 2.3 算法设计与开发

**Backbone 选择：**

| 模型 | 参数量 | 从零训练 Top-1（参考） | 100ep 训练时间(4060) | 选择理由 |
|------|--------|----------------------|---------------------|---------|
| StarNet-S2 | 12M | ~68% | ~3 天 | 快速实验筛选用 |
| **ResNet-50** | 25M | **~72-74%** | **~5-6 天** | **主力模型，稳定可靠** |
| ConvNeXt-V2-T | 28M | ~79-81% | ~8 天 | 备选冲刺模型 |

选择 ResNet-50 作为主力模型的理由：
1. 训练稳定性高，从零训练有大量参考基准
2. 5-6 天可完成 100 epoch，允许多次实验迭代
3. 参数量适中，RTX 4060 可用 batch=128 + 梯度累积 2 步

**噪声鲁棒损失函数：**

| 损失函数 | 核心思想 | 超参数 | 适用场景 |
|---------|---------|--------|---------|
| CE + Label Smoothing | 软化标签分布 | smoothing=0.1 | 低噪声基线 |
| SCE | 对称化 CE，抑制噪声梯度 | α=0.1, β=1.0 | 中等噪声 |
| GCE | 截断大 loss 样本的梯度 | q=0.7 | 高噪声 |
| ELR | 历史预测正则化 | β=0.9, λ=3.0 | 需要样本级记忆 |

**训练策略：**
- 优化器：SGD + Momentum(0.9) + Weight Decay(1e-4)
- 学习率：Warmup(5ep, linear) → Cosine Annealing
- 混合精度：AMP(FP16) 减半显存占用
- 梯度累积：2 步，等效 batch size = 256
- EMA：decay=0.9999，用于验证和最终推理
- 梯度裁剪：max_norm=5.0

### 2.4 模型训练与优化

**RTX 4060 适配策略：**
- TF32 加速：`torch.backends.cuda.matmul.allow_tf32 = True`
- cuDNN Benchmark：`torch.backends.cudnn.benchmark = True`
- Channels Last 内存格式：显存节省 ~10%
- AMP 自动混合精度：显存减半，速度 2x
- DataLoader 优化：num_workers=4, pin_memory=True

**实验流程（快速筛选 → 正式训练）：**
1. StarNet-S2 + 10% 子集 + 30 epochs：快速对比不同 Loss（~30 分钟/组）
2. ResNet-50 + 10% 子集 + 30 epochs：确认最优 Loss 在大模型上的表现
3. ResNet-50 + 全量数据 + 100 epochs：正式训练（~5-6 天）

**超参搜索空间：**
- 学习率：{0.05, 0.1, 0.2}
- SCE α：{0.1, 0.3, 0.5}
- SCE β：{0.5, 1.0}
- GCE q：{0.5, 0.7, 0.9}

### 2.5 测试与验证

**验证集评估：**
- 使用 EMA 模型进行验证（比原始模型更稳定）
- 指标：Top-1 Accuracy、Top-5 Accuracy
- 每 epoch 评估一次，保存最优 checkpoint

**测试集推理流程：**
```
加载 best.pth → EMA 模型 → 10 万张推理 → 排序 → result.csv
```

**CSV 格式：**
```
filename,label
test_00000001.JPEG,n01440764
test_00000002.JPEG,n02102040
...
```

## 三、算法创新点

1. **分层噪声处理策略**：通过数据分析识别高噪声类别（Top-20），针对性选择损失函数参数，而非全局统一处理
2. **快速筛选实验范式**：利用轻量级 StarNet（12M 参数）在 10% 子集上快速验证策略有效性，再迁移到 ResNet-50 全量训练，实验效率提升 10x
3. **工程化可复现方案**：完整的 Docker 容器化 + 一键复现脚本，确保从训练到推理的全流程可复现

## 四、问题与思考

### 开发过程中遇到的困难及解决方案

| # | 问题 | 影响 | 解决方案 |
|---|------|------|---------|
| 1 | Docker 构建上下文不支持 `../` 相对路径 | 赛事方无法复现 | Dockerfile 移至仓库根目录，所有 COPY 相对根路径 |
| 2 | run.sh 引用不存在的配置文件 | 容器启动即失败 | 改为环境变量 CONFIG 读取，提供默认值 |
| 3 | GitHub HTTPS 被 TLS 重置 | 无法协作推送代码 | 切换 SSH 走 443 端口（ssh.github.com:443） |
| 4 | 依赖未锁版本，torch 2.6 接口漂移 | 跨机器行为不一致 | requirements.txt 加上下界约束 |
| 5 | 10% 子集数据准备脚本 val 目录缺失 | 训练 pipeline 验证集评估失败 | 用 LOC_val_solution.csv 重建 val 的类别子文件夹结构 |
| 6 | autodl-tmp1 上 train 只解压了 123/1000 类 | 模型只能学到 12.3% 的类别 | 统一数据源，symlink 到完整的 1000 类数据 |
| 7 | StarNet config 的 num_classes 设为 123 | 模型输出维度与实际类别数不匹配 | 修正为 1000 |

### 进一步优化思考

- Docker 构建层缓存优化：先 COPY requirements.txt 再 pip install，源码变动不触发重装
- WandB 离线模式适配无外网赛事机器
- 考虑 Mixup/CutMix 集成到训练循环中进一步提升泛化能力
- 长尾分布可尝试 ClassBalancedSampler 或 focal loss 变体
